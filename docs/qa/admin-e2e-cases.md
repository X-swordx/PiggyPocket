# 后台管理系统 · 端到端手工验收用例

- 适用版本：M0–M4 交付
- 前置：后端 `nest-service` 已启动（`npm run start:dev`），已执行全部 migration；前端 `admin` 已启动（`pnpm dev`，默认 http://localhost:5174）
- 账号：`superadmin / admin123456`

## 环境准备

```bash
# 1. 后端
cd nest-service
npm run migration:run     # 首次或有新 migration 时
npm run start:dev

# 2. 前端
cd admin
pnpm install              # 首次
pnpm dev
```

若要验证角色权限（TC-13/TC-14），先用超管在「系统管理 → 管理员账号」建两个账号：

| 用户名 | 密码 | 角色 |
| --- | --- | --- |
| `op_test` | `test123456` | operator |
| `viewer_test` | `test123456` | viewer |

## TC-01 登录与登出

| 步骤 | 预期 |
| --- | --- |
| 1. 打开 http://localhost:5174 | 跳转到 `/login` |
| 2. 输入错误密码提交 | 顶部 toast 提示「用户名或密码错误」，停留在登录页 |
| 3. 输入 `superadmin / admin123456` 提交 | 进入首页，侧栏显示 5 个模块图标 |
| 4. 点右上头像 → 退出登录 | 回到 `/login`，刷新后不会自动登录 |
| 5. 重新登录后进入「系统管理 → 操作日志」 | 能看到刚才的 `login` 与 `logout` 两条记录，含 IP |

## TC-02 临期食品 — 列表与筛选

| 步骤 | 预期 |
| --- | --- |
| 1. 进入「临期食品」 | 列表加载，无数据时显示「暂无数据」 |
| 2. 「状态」选「已过期」→ 搜索 | 只剩到期日早于今天的记录，状态标签为红色 |
| 3. 「按用户过滤」下拉输入昵称关键字 | 下拉出现匹配用户（含头像与 openid 尾号） |
| 4. 点「重置」 | 三个筛选条件清空，列表恢复全量 |

## TC-03 临期食品 — 新增

| 步骤 | 预期 |
| --- | --- |
| 1. 点「新增食品」 | 弹出对话框，「所属用户」可选 |
| 2. 不填任何字段直接保存 | 用户/名称/保质期三项显示必填校验 |
| 3. 选用户、填名称、选到期日、点「点击上传」选一张图 | 上传成功 toast，缩略图显示 |
| 4. 保存 | toast「已创建」，对话框关闭，列表出现该条且「所属用户」列显示昵称 |

> 若 `.env` 未配 `OSS_*`，第 3 步上传会失败但其余字段仍可保存 —— 属预期。

## 已知限制（非缺陷）

| 项 | 说明 |
| --- | --- |
| 小程序端已校验用户禁用 | ✅ 已处理：`wechat-login` 命中已有用户时判断 `status !== 1` 并返回 403「账号已被禁用，请联系管理员」；mobile 端 `refreshCurrentUser` 捕获后清除本地缓存。 |
| 角色权限已支持动态配置 | ✅ 已处理：新增 `admin_role_permissions` 表，后台「系统管理 → 角色权限」页可对 operator/viewer 勾选权限码；superadmin 固定全权限不可改。 |
| Dashboard 无自动刷新 | 需手动刷新页面。 |
| 无后台创建订单 | 订单只能从小程序发起，后台仅管理。 |
| admin Docker 镜像未在本机验证 | ⚠️ 开发机拉不通 Docker Hub，[Dockerfile](../../admin/Dockerfile) 需在云服务器首次构建时验证。 |
